# Catalyst — working prototype

One working mock of **Catalyst** (IFS Copperleaf), built up mini flow by mini flow, until it works like real software. It's used for usability tests, demos and marketing. Two designers feed flows in parallel: Shiny (`shinyc01`) and Mahsa (`mkarimi727`). Neither is a developer, so **you do all the code, data, testing and git work.**

**To add, change or publish a flow, use the `catalyst-flow-builder` skill** (`.claude/skills/catalyst-flow-builder/`). It runs the whole procedure, including safe syncing with GitHub.

- Live site: https://shinyc01.github.io/catalyst-prototype/ (deployed from `main` by GitHub Pages)
- Repo: https://github.com/shinyc01/catalyst-prototype (public)

## Read before building anything
1. `context/product.md`: what Catalyst is, its stages, and Cooper.
2. `context/glossary.md`: the terms used here.
3. The `context/logic/` files the feature touches (risk, investments, …).
4. The `context/flows/` file for the journey, and the `context/screens/` file for each screen you touch.
5. `context/data/whistler.md`: the mock data layer.
6. `context/decisions.md` and `context/open-questions.md`: what's already settled, and what isn't.

## Standing rules
- **Git safety first.** Never work on `main`, and always go through `scripts/sync.sh` (start → save → finish). Never discard anyone's work. Details are in the skill's `references/git.md`.
- **No plan approval.** Build directly, then hand over for review. Ask only about real conflicts or product decisions.
- **The Figma frame is the spec.** Match each frame's layout, controls, labels and card order. Logic only changes the *values* shown; it never adds, renames or moves UI. If logic needs UI that isn't in the frame, flag it as non-DS. Screenshot the frame before building and compare side by side after.
- **Use Catalyst Design System 2.0 only.** Use the pinned copy in `vendor/ds2/` (look components up with `scripts/entry.sh`; update deliberately with `scripts/update-ds.sh`). Anything not in the kit is wrapped in `NDS`, which shows a "Not in DS" flag.
- **Use tokens only.** No hex or rgba values in app code; `scripts/check.mjs` enforces this.
- **There is one data layer and one logic source.** All data lives in `shared/`:
  - real Whistler demo records, which are generated;
  - invented names;
  - `[Added]` gaps, filled consistently;
  - the risk model;
  - per-screen content.

  Never type a number into a screen, and never fork a copy. The same record must show the same values everywhere.
- **Every fact gets a source tag:** `[Confirmed]` (said by the designer), `[Figma]` / `[Confluence]` (taken from a source), `[Assumed]` (invented, needs confirming) or `[Added]` (data filled in). Never present an `[Assumed]` number as truth.
- **Conflicts get asked about.** If a new request contradicts the context, raise it; don't override it silently.
- **Every flow stays a flow.** Each mini flow gets a file in `app/flows/` with a guided tour. Keep older tours working.
- **Hand over with a link.** Give the live link once the change is merged, or a local link while testing, plus deep links (`#screen?…`) for the new screens.
- **Update the context after each round,** in the same pull request.

## Layout
```
index.html                the app (served as-is by GitHub Pages; no build step)
app/
  styles.css              layout CSS, tokens only
  ui.jsx                  kit imports (IFS), NDS flag, shared flow data (Cooper scripts, idea alternatives)
  map.jsx                 MapLibre 3D map, legend, map tools
  store.jsx               usePersisted: demo state that survives reloads ("Reset demo" clears it)
  screens/*.jsx           one file per screen (command, explore, study, build, …)
  flows/NNN-<id>.js       one file per mini flow + its guided tour; index.js is GENERATED (scripts/manifest.py)
  tour.jsx                Flows panel, guided tour, prototype controls, presentation mode
  main.jsx                routing (hash ↔ state), app shell
shared/                   the mock data layer (plain JS, loaded in this order)
  whistler-data.js        REAL Whistler demo records (GENERATED by scripts/make-whistler-data.py; don't hand-edit)
  names.js                invented people list + company (Alder Ridge Energy); names are replaced in the generator, never stored real
  whistler-additions.js   [Added]: geography, cluster, personas, tolerance, lens sensitivity, BCR rule
  catalyst-model.js       risk model, area-risk grid, lens catalogue, study helpers
  whistler-command.js     Command content per persona (real + [Added])
vendor/ds2/               pinned Catalyst Design System 2.0 (js, css, api.md, rules, icons, tokens, VERSION.txt)
scripts/
  sync.sh                 safe git: setup · status · start · save · update · finish · home
  check.mjs               data / flow / token checks (also run on GitHub for every pull request)
  manifest.py             regenerates app/flows/index.js
  make-whistler-data.py   pulls records from the copperleaf-demo-data skill
  update-ds.sh            re-pins DS 2.0 · entry.sh: look up DS components
  build-standalone.sh     offline single-file copy → share/ (git-ignored)
context/                  product knowledge (read first, keep current)
prototypes/               LEGACY single-file prototypes v1–v7 — on Shiny's Mac only, not in the repo (pre-rename data)
.claude/skills/catalyst-flow-builder/   the skill
```
